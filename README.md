# Sushi Mir — версія для Netlify зі спільним каталогом

## Що змінено
- Каталог товарів тепер зберігається у **Netlify Blobs**, а не в `localStorage`.
- Додавання, редагування, видалення, очищення та відновлення каталогу записуються на сервер.
- Усі відвідувачі бачать один спільний каталог. Відкриті сторінки перевіряють оновлення приблизно кожні 15 секунд.
- Початковий каталог автоматично створюється під час першого запиту.
- Кошик і вибір теми залишилися локальними для кожного браузера.
- **Telegram не змінювався:** `app.js`, `bot.py` та `netlify/functions/order.js` збережені в частині Telegram-надсилання замовлень.

## Як оновити сайт на Netlify
1. Розпакуйте ZIP.
2. Завантажте в GitHub файли та папки з цієї папки (не завантажуйте ZIP як один файл).
3. У Netlify відкрийте свій сайт → **Project configuration / Site configuration → Build & deploy → Continuous deployment** та переконайтеся, що підключено потрібний GitHub-репозиторій.
4. Зробіть commit і push оновлених файлів у цей репозиторій. Netlify автоматично запустить новий deploy.
5. У Netlify → **Environment variables** додайте:
   - `ADMIN_PASSWORD` = `adminadmin123mir.com`
   - Ваші чинні `BOT_TOKEN` та `ADMIN_CHAT_ID` залиште без змін, якщо вони вже налаштовані.
6. Запустіть **Deploys → Trigger deploy → Deploy site**, якщо автоматичний deploy не стартував.

Build settings з `netlify.toml`:
- Build command: порожньо
- Publish directory: `.`
- Functions directory: `netlify/functions`

`package.json` встановить `@netlify/blobs`, а Netlify Functions використовуватимуть його для спільного сховища. Окрему базу даних створювати не потрібно.

## Як перевірити синхронізацію
1. Відкрийте сайт у двох браузерах або на двох пристроях.
2. У першому відкрийте адмін-панель і видаліть товар.
3. Другий браузер має показати оновлений каталог автоматично протягом приблизно 15 секунд (або після перезавантаження).
4. Додайте товар назад, якщо він потрібен.

## Важливо про пароль адмінки
Пароль залишений таким самим, як у попередній версії. Для запису каталогу сервер також перевіряє змінну `ADMIN_PASSWORD`. Оскільки поточна адмін-панель — це стартова/демонстраційна авторизація на фронтенді, пароль присутній у JavaScript. Для повноцінного комерційного захисту потрібна окрема серверна авторизація.

## Telegram
Надсилання замовлень у Telegram навмисно не перероблялося. Якщо Telegram працює у поточному deploy, не змінюйте його налаштування. Файл `netlify/functions/order.js` також залишений як був.
